# 🔐 Архитектура безопасности, аутентификация и управление доступом

Данный документ описывает архитектуру корпоративной безопасности CARINA, расположенную в каталогах [`src/utils/security/`](../../src/utils/security) и [`src/utils/security_manager.py`](../../src/utils/security_manager.py). В нем подробно рассматриваются аутентификация пользователей, криптографическое хеширование паролей, защита от атак методом подбора (brute-force), изоляция схем базы данных и парадигма конфигурации 12-Factor App.

## 1. Обзор архитектуры безопасности

CARINA управляет критически важной муниципальной инфраструктурой жизнеобеспечения. Несанкционированный доступ или повышение привилегий злоумышленником могут нарушить работу светофорных контроллеров, спровоцировав ДТП или транспортный коллапс. Для предотвращения подобных угроз система реализует:

1. **Детерминированное хеширование паролей:** Криптографический алгоритм `bcrypt` с солью и настраиваемым фактором трудоемкости.
2. **Защита от перебора паролей (Lockdown Engine):** Ограничение частоты запросов по IP и имени пользователя с прогрессивным временем блокировки.
3. **Ролевая модель доступа (RBAC):** Дифференцированные права доступа для ролей `OPERATOR`, `ENGINEER` и `ADMIN`.
4. **Изоляция секретов по методологии 12-Factor:** Полное исключение конфиденциальных параметров из исходного кода через переменные файла `.env`.

```text
 Клиент (Flet UI / CLI)
          │
          ▼
 ┌──────────────────┐       Проверка учетных данных        ┌──────────────────┐
 │   AuthService    │ ───────────────────────────────────> │  Хешер Bcrypt    │
 └────────┬─────────┘                                      └──────────────────┘
          │
          ├──> [Проверка на перебор] ──> LockdownManager (Макс. 5 попыток, 15 мин блокировки)
          │
          └──> [Извлечение польз.]   ──> UserRepository (Изолированная схема PostgreSQL / SQLite)
```

## 2. Обзор базовых модулей

### 2.1 Хеширование паролей и криптография (`hasher.py`)
Расположен в [`src/utils/security/hasher.py`](../../src/utils/security/hasher.py):
- Реализует криптографическое хеширование на базе библиотеки `bcrypt`.
- Автоматическая генерация соли (по умолчанию $2^{12}$ раундов).
- Безопасное по времени побайтовое сравнение строк, защищающее от атак по сторонним каналам тайминга (timing attacks).

### 2.2 Защита от перебора паролей (`lockdown.py`)
Расположен в [`src/utils/security/lockdown.py`](../../src/utils/security/lockdown.py):
- Отслеживает неудачные попытки входа в разрезе логина и клиентского IP-адреса.
- Активирует автоматическую блокировку учетной записи после 5 последовательных неудачных попыток.
- Применяет экспоненциально возрастающий период блокировки (по умолчанию: 15 минут).

### 2.3 Сервис пользователей и репозиторий (`user_service.py` и `user_repository.py`)
- [`src/utils/security/user_repository.py`](../../src/utils/security/user_repository.py): Прямое взаимодействие с SQL-хранилищем для записей пользователей, сессий и журналов доступа.
- [`src/utils/security/migrator.py`](../../src/utils/security/migrator.py): Автоматическая инициализация и миграция таблиц `users` и `audit_log` в схемах SQLite и PostgreSQL.

## 3. Конфигурация 12-Factor и переменные окружения

Все конфиденциальные параметры должны определяться исключительно в файле [`.env`](../../.env.example) и ни в коем случае не фиксироваться в репозитории Git:

```bash
# --- Режим выполнения ---
# 'development': разрешает стандартные демонстрационные учетные данные (admin / Admin@Carina2026!).
# 'production': СТРОГО БЛОКИРУЕТ стандартные пароли; требует заданных хешей секретов.
CARINA_ENV=production

# --- Инициализация суперпользователя ---
CARINA_SUPERUSER_USER=admin_traffic
CARINA_SUPERUSER_PASSWORD=YourStrongPasswordHere!
CARINA_SUPERUSER_HASH=$2b$12$e8x...

# --- Учетные данные базы данных ---
CARINA_DB_USER=carina_sec
CARINA_DB_PASSWORD=database_secure_password
CARINA_DB_HOST=127.0.0.1
CARINA_DB_PORT=5432
CARINA_DB_NAME=carina_data
CARINA_DB_SCHEMA=schema_carina

# --- Пароль SNMP / Контроллеров ---
CARINA_SNMP_COMMUNITY=YourSnmpCommunityString

# --- Параметры экспорта внешней телеметрии ---
CARINA_MQTT_HOST=127.0.0.1                     # Локальный брокер или https://tunnel.ngrok-free.dev/api/telemetry
CARINA_MQTT_PORT=1883
CARINA_MQTT_USER=
CARINA_MQTT_PASSWORD=
```

## 4. Рекомендации по усилению безопасности в промышленной эксплуатации (Hardening)

1. **Смена Community String в SNMP:** Категорически запрещено использовать стандартную строку `"public"` на боевых контроллерах.
2. **Ограничение сетевых интерфейсов IPC и gRPC:** В промышленном контуре привязывайте порты gRPC (`50051`) и WebSocket (`8080`) к изолированным технологическим VLAN или адресу `127.0.0.1`, используя обратный прокси с шифрованием TLS.
3. **Принцип наименьших привилегий в БД:** Предоставляйте сервисному пользователю базы данных только привилегии `SELECT`, `INSERT` и `UPDATE` в рабочей схеме.
4. **Отказоустойчивость контроллеров (Fail-Safe):** Убедитесь, что все дорожные контроллеры аппаратно настроены на переход в локальную суточную программу или режим желтого мигания при обрыве связи со шлюзом.
